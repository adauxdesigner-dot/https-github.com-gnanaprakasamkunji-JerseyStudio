# Frontend Acceptance Checklist

## Design system
- [ ] Shared color, typography, spacing, border, radius, and focus tokens exist.
- [ ] Shared components use the tokens consistently.
- [ ] Buttons, inputs, dialogs, tables, alerts, and status states are documented.
- [ ] Contrast, keyboard navigation, focus, and accessible labels are checked.
- [ ] No unauthorized copying of reference product branding/assets.

## App shell
- [ ] Navigation works.
- [ ] Main screens have consistent page hierarchy.
- [ ] Save status and local/offline status are accurate.
- [ ] No cloud-sync UI is shown.
- [ ] Every visible button has a real action or an explained disabled state.

## Editor
- [ ] Canvas is interactive.
- [ ] Add/edit/move/delete actions work.
- [ ] Properties panel reflects the selected element.
- [ ] Save and reopen preserve the design.
- [ ] Unsaved changes are not silently lost.
- [ ] Undo/redo works where claimed.
- [ ] Front/back view selector works where claimed.

## Roster and export
- [ ] Import preview and field mapping work.
- [ ] Validation errors are actionable.
- [ ] Batch progress is based on real job status.
- [ ] Exported files are checked for content and dimensions.
- [ ] No roster or artwork is sent to cloud services.

## Visual QA
- [ ] Dashboard, editor, roster, preview, export, settings, and authorization states are reviewed.
- [ ] Empty, loading, error, success, and disabled states are reviewed.
- [ ] Screenshots checked at wide, medium, and narrow desktop window sizes.
- [ ] Windows and macOS differences are tested.
- [ ] No console errors or unhandled UI failures remain.
